## 1. 이 PoC가 확인한 것과 확인하지 못한 것

| | 내용 |
|---|---|
| **확인한 것** | 누끼 전용 모델이 범용 분할 모델보다 이 업무에서 확실히 낫다 (7/12 대 0/12) |
| | 실패 유형이 5가지로 정리된다 (그림자·반사·털·약한 대비·상품 지목 불가) |
| | 실패를 미리 표시하는 것이 대체로 가능하다 (5건 중 4건, 오탐 0건) |
| | SAM이 내주는 신뢰도 점수는 이 판정에 쓸 수 없다 |
| **확인하지 못한 것** | 현행 수작업이 실제로 얼마나 걸리는가 → 성공 기준 B 판정 불가 |
| | 사후에 정한 임계값이 새 사진에서도 유지되는가 |
| | 실제 업무 사진(공개 불가 이미지)에서 같은 결과가 나오는가 |

## 2. 한계

### 2-1. 성공 기준 B를 재지 못했다 (가장 큰 구멍)

작업 PC에 Photoshop이 없어 현행 수작업 시간을 측정하지 못했고, 공개 수치는 전부 누끼 서비스·
AI 툴 판매사 자료라 근거로 쓰지 않았다. **개선 폭을 모르는 상태다.**

이것이 왜 치명적인가 — 품질에서는 기준선(사람)이 이겼다. 자동화의 값어치는 전적으로 "얼마나
빨라지는가"에 달려 있는데, 그 숫자가 없다. **다음 단계의 1순위는 모델이 아니라 측정이다.**

### 2-2. 임계값을 결과를 보고 정했다

`경계 애매도 0.04`, `테두리 접촉 0.01`은 12장의 결과를 보고 두 무리가 갈리는 자리를 찾아
정한 값이다. 이 12장에서는 갈렸지만, **새 사진에서도 갈린다는 보장이 없다.**

특히 이 샘플은 서로 뚜렷하게 다른 12장이다. 실제 이커머스 작업은 같은 상품을 여러 각도에서
찍은 비슷한 사진이 대량으로 들어오는데, 그런 묶음에서는 값의 분포가 좁아져 구간이 사라질 수 있다.

### 2-3. 샘플이 실제 업무 사진이 아니다

제출물이 공개 저장소라 공개 이미지(Pexels)를 썼다. 실제 상품 촬영본은 조명·배경·구도가
사내 규격으로 통일돼 있어 오히려 쉬울 가능성이 높지만, **확인된 바 없다.**

또한 12장은 판단을 세우기에는 충분해도 임계값을 정하기에는 적다.

### 2-4. BiRefNet을 실행하지 못했다

세 번째 후보로 넣은 BiRefNet은 **전체 판본과 경량 판본(224MB) 모두 무료 Colab에서 메모리
초과(약 11.6GB 사용, 한도 약 13GB)로 강제 종료**됐다. 따라서 "전용 모델 중 더 최신 모델이
나은가"는 확인하지 못했다.

이것 자체가 도입 판단에 들어가는 정보다 — **무료 환경에서 돌아가지 않는 모델은 그 환경에서는
후보가 아니다.** 사내 PC의 RAM이 32GB 이상이면 다시 후보가 된다.

### 2-5. 판정 항목을 하나로 좁혔다

"배경이 제거되었는가" 하나만 판정했다. 그림자 재합성, 규격 캔버스 배치, 썸네일 리사이즈 등
실제 업무의 나머지 공정은 다루지 않았다.

## 3. 다음 단계 — 실패 유형별로

| 실패 유형 | 해당 | 다음에 시도할 것 |
|---|---|---|
| 상품 지목 불가 | `h05` | **모델 2개 연결**: 텍스트로 상품을 지목(GroundingDINO)해 박스를 얻고 그 박스를 SAM에 프롬프트로 넘긴다. 또는 U²-Net 마스크의 무게중심을 SAM의 점 프롬프트로 넘겨 두 모델을 잇는다 |
| 털 경계 뭉개짐 | `h03` | `rembg`의 **알파 매팅(alpha matting)** 옵션. 경계를 반투명 단계로 나눠 계산한다 |
| 그림자 잔상 | `e07` | 그림자 제거를 **별도 후처리 단계**로 분리. 누끼와 같은 모델에 맡기지 않는다 |
| 반사(거울상) | `h02` | 촬영 단계에서 반사면을 쓰지 않도록 규격화. 모델로 푸는 것보다 촬영으로 푸는 편이 확실하다 |
| 약한 대비 | `e04` | 촬영 배경색을 상품과 반대로 지정. 이것도 모델 교체로는 해결되지 않는다 |

**다섯 중 셋(`h05` `h02` `e04`)은 촬영·입력 조건으로 해결하는 편이 빠르다.**
수업 정리의 마지막 항목 그대로다 — *"판정 항목을 정하면 자료를 어떻게 모을지가 함께 정해진다.
모델 교체로 해결되지 않는다."*

## 4. 다음 단계 — 순서

1. **현행 수준 측정 (1순위).** 담당자가 Photoshop에서 20장을 처리하고 장당 시간과 오류 수를
   센다. 이것 없이는 성공 기준 B도, 도입 여부도 판정할 수 없다.
2. **임계값 재검증.** 이 12장에 쓰이지 않은 새 사진 20~30장에서 같은 규칙이 성립하는지 본다.
   두 무리가 겹치면 이 구성으로는 "미리 표시"를 만들 수 없다는 결론이 된다.
3. **촬영 규격 초안.** 3절에서 촬영으로 풀리는 세 유형에 대해 배경색·반사면 금지·상품 단독
   촬영 규칙을 문서로 만든다.
4. **알파 매팅과 모델 연결 실험.** 1~3이 끝난 뒤. 순서를 바꾸면 "성능은 좋아졌는데 도입할
   값이 있는지는 여전히 모르는" 상태가 된다.

## 5. 실제 도입까지 필요한 것

| 항목 | 현재 | 도입하려면 |
|---|---|---|
| **데이터** | 공개 이미지 12장 | 실제 상품 사진 50~100장 + 기존 누끼 결과물(정답) |
| **비용** | 0 (무료 Colab / 오픈 가중치) | 사내 PC 또는 서버 1대. GPU 없이 CPU로도 장당 수 초면 가능 |
| **운영 방식** | 스크립트 수동 실행 | 촬영 → 폴더 투입 → 자동 처리 → **표시된 장만** 디자이너 검수 |
| **품질 관리** | 사람이 전수 검사 | 표시 규칙 재검증 후 검수 범위 축소 |
| **라이선스** | 전부 상업 사용 가능 확인 | 모델 교체 시 재확인 (특히 AGPL 계열 주의) |

## 6. 오늘의 회고

수업이 남기라고 한 네 가지.

**1. 적은 지점 중에서 고른 것과 뺀 것의 차이는?**
누끼 작업을 골랐다. 판정 기준이 이미 있고("경계가 깔끔한가"), 과거 결과물이 정답으로 남아 있고,
틀려도 디자이너가 다시 하면 되며, 상품 수만큼 반복된다 — 네 조건을 다 만족했다.
뺀 지점들은 "틀렸을 때" 칸에서 걸렸다.

**2. 성공 기준의 숫자를 어디서 가져왔는가? 현행 수준을 실제로 재 보았는가?**
품질 기준 9/12는 시간 기준에서 역산했다(불합격 4장 미만이어야 전체가 1/3 이하가 된다).
**현행 수준은 재지 못했다.** Photoshop이 없었고, 공개 수치는 전부 판매사 자료였다.
이것이 이 PoC의 가장 큰 구멍이고, 기준을 적기 전에 현행을 먼저 재야 했다.

**3. 실행 위치나 라이선스 때문에 제외한 후보가 있었는가? 점수로는 몇 위였는가?**
remove.bg 등 외부 API를 실행 위치 조건으로 제외했다. **점수를 재지 않았으므로 몇 위인지 모른다
— 그게 조건으로 먼저 거른다는 것의 의미다.** 점수부터 매겼다면 상위에 왔을 가능성이 높고,
"사진이 외부로 나간다"는 사실은 각주로 밀렸을 것이다.

**4. 기준을 넘지 못한 항목이 있다면, 다음에 무엇을 바꿔 다시 확인하겠는가?**
기준 A(7/12, 9 필요)가 미달이다. 실패 5건 중 셋은 모델이 아니라 촬영·입력 조건 문제였다.
그래서 다음에 바꿀 것은 모델이 아니라 **촬영 규격**이고, 그다음이 알파 매팅과 모델 연결이다.
그 전에 현행 수준 측정(기준 B)을 먼저 끝낸다.
