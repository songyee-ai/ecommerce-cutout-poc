# 모델 선정 근거

확인 날짜: **2026-09-22** · 값과 라이선스, 지원 범위는 바뀌므로 확인 날짜를 함께 남긴다.

---

## 1. 후보를 어떻게 벌렸는가

흔한 후보 구성은 한 모델의 대·중·소 세 등급이다. 그렇게 놓으면 표에 나타나는 것은 크기가 만드는
차이뿐이고, 큰 것이 정확하고 느리다는 결론은 재 보기 전에도 알던 것이다.

그래서 **크기가 아니라 종류로** 벌렸다. 갈리는 축은 셋이다.

| 축 | 이 PoC에서 갈린 지점 |
|---|---|
| **실행 위치** | 전부 로컬 실행 가능한 것만 남겼다. 외부 API는 조건에서 제외(→ 2절) |
| **만들어진 목적** | **범용** 분할 모델(SAM) vs **누끼 전용** 모델(U²-Net, BiRefNet) |
| **결과의 형태** | **신뢰도 점수를 함께 주는 것**(SAM) vs **마스크만 주는 것**(전용 모델들) |

세 번째 축이 이 PoC에서 특히 중요하다. 성공 기준 C("손봐야 할 장을 미리 표시")는 결과의 형태에
직접 달려 있다. 정확도가 같아도 점수를 안 주는 모델로는 그 기준을 만족시킬 수 없다.

## 2. 점수를 매기기 전에 조건으로 걸러낸 것

수업 지침대로 **제외 조건은 점수와 섞지 않았다.** 감점 항목으로 다루면 다른 항목이 높을 때 그
후보가 다시 1위로 올라오고, 쓸 수 없다는 사실이 각주로 밀린다.

### 조건 1 — 사진을 외부로 보낼 수 없다

미공개 신상품 사진과 거래처 제공 이미지가 포함된다.

| 제외된 후보 | 이유 |
|---|---|
| remove.bg API | 사진을 업로드해야 동작한다. 성능과 무관하게 제외 |
| Adobe Photoshop API / Firefly | 같은 이유 |
| 각종 온라인 배경제거 서비스 | 같은 이유 |

**이 조건이 없었다면 이 후보들이 표의 상위에 왔을 가능성이 높다.** 성능이 가장 좋은 후보를 쓸 수
없는 상황은 실무에서 흔하고, 그때 무엇을 고르는지가 판단이다.

### 조건 2 — 라이선스가 상업적 사용을 허용해야 한다

연구 목적 공개 모델에는 비상업 조건이 붙은 경우가 흔하다. 저장소 첫 화면 표시만 보면 놓칠 수 있고,
**코드와 가중치의 조건이 다르게 붙어 있기도 하다.** 그래서 설치한 패키지의 배포 정보와 원저작
저장소를 각각 확인했다.

| 대상 | 종류 | 라이선스 | 확인 방법 |
|---|---|---|---|
| `torch` 2.11.0+cu128 | 코드 | BSD-3-Clause | 설치 패키지 배포 정보 |
| `transformers` 5.16.1 | 코드 | Apache 2.0 | 설치 패키지 배포 정보 |
| `rembg` 2.0.85 | 코드 | MIT | 설치 패키지 배포 정보 + GitHub API |
| `onnxruntime` 1.30.0 | 코드 | MIT | 설치 패키지 배포 정보 |
| `facebook/sam-vit-base` | **가중치** | Apache 2.0 | Hugging Face 모델 정보 |
| `ZhengPeng7/BiRefNet` | **가중치** | MIT | Hugging Face 모델 정보 |
| U²-Net (`xuebinqin/U-2-Net`) | **가중치** | Apache 2.0 | GitHub API |

전부 상업적 사용이 가능해 라이선스로 제외된 후보는 없었다. (원본 SAM 저장소 `facebookresearch/segment-anything`의
코드는 Apache 2.0이고, 이 PoC는 그 코드 대신 `transformers`의 구현을 쓴다.)

> 참고로 자세 추정에 널리 쓰이는 Ultralytics YOLO 계열은 AGPL이라, 닫힌 제품에 넣어 배포하면
> 소스 공개 의무가 걸린다. 이 PoC에서는 쓰지 않았지만 다음 단계에서 상품 탐지를 붙일 때
> 후보로 올라올 수 있어 여기 적어 둔다.

## 3. 남은 후보

| | **SAM** | **U²-Net** | **BiRefNet** | **기준선: 현행 수작업** |
|---|---|---|---|---|
| 정식 이름 | `facebook/sam-vit-base` | `u2net` (rembg 기본) | `birefnet-general` (rembg) | Photoshop 피사체 선택 |
| 만들어진 목적 | 범용 분할 | 배경 제거 전용 | 배경 제거 전용 | — |
| 실행 위치 | 로컬/사내 가능 | 로컬/사내 가능 | 로컬/사내 가능 | 로컬 |
| 상품 지목 방식 | **점 프롬프트 필요** | 불필요 (자동) | 불필요 (자동) | 사람이 봄 |
| 신뢰도 점수 | **있음** (`iou`, 안정도) | 없음 (알파만) | 없음 (알파만) | 사람의 확신 |
| 라이선스 | Apache 2.0 | Apache 2.0 | MIT | 상용 구독 |

### SAM을 고른 이유

수업에서 다룬 분할 모델이고, **신뢰도 점수를 함께 내주는 유일한 후보**다. 성공 기준 C가 여기에
직접 걸려 있다. SAM은 마스크마다 `iou_scores`(모델이 스스로 매긴 마스크 품질 예측)를 돌려주고,
이진화 전 로짓이 남아 있어 경계를 흔들었을 때 면적이 유지되는 정도(안정도)를 따로 계산할 수 있다.

**한계도 분명하다. SAM은 자동이 아니다.** 사진을 주면 알아서 "이게 상품이다"를 고르지 않는다.
어디를 딸지 지목해 주어야 한다. 이 PoC는 이커머스 상품 사진이 상품을 가운데 놓는다는 관행을 이용해
**사진 중앙에 점 하나**를 자동으로 찍는 방식을 썼다(`--sam-point center`). 이것이 성립하지 않는 사진
(`h05` 소품 스타일링컷)에서 무엇이 일어나는지가 이 PoC가 확인하려는 것 중 하나다.

크기는 `vit-base`를 골랐다. `vit-huge`(2.4GB)를 쓰면 정확도가 오르겠지만, 이 PoC의 질문은
"모델을 키우면 좋아지는가"가 아니라 "이 자리에 자동 분할을 넣을 수 있는가"이기 때문이다.

### U²-Net과 BiRefNet을 고른 이유

**전용 모델이 좁은 일에서 범용 모델보다 나은지**를 확인하려면 전용 쪽이 후보에 있어야 한다.
둘 다 배경 제거만 하도록 만들어졌고 프롬프트가 필요 없다. U²-Net은 `rembg`의 기본값이라 사실상
업계 기준선이고, BiRefNet은 더 최근 모델이라 전용 모델 안에서의 차이도 함께 볼 수 있다.

### 기준선을 후보에 넣은 이유

지금 그 업무를 처리하는 방식이 이미 있다. 이것을 후보에 넣지 않으면 새로 만든 것이 쓸 만한지
판단할 기준선이 없고, 개선 폭을 모르는 상태에서 도입을 결정하게 된다.

**기준선이 이기면 그때 나오는 결론은 "AI가 쓸모없다"가 아니라 "이 업무에는 지금 방식이 낫다"이고,
그것도 PoC의 결과다.**

## 4. 공개 순위표를 쓰지 않은 이유

배경 제거·분할 모델의 공개 벤치마크는 후보를 좁히는 데까지만 썼다. 그 표는 이 PoC의 자료로 잰 것이
아니다. 특히 이커머스 상품 사진은 흰 배경 위 흰 상품, 투명 용기, 소품 스타일링컷 같은 구성이 많은데
일반 분할 벤치마크에는 이런 구성의 비중이 낮다.

그래서 최종 판단은 `data/samples/`의 12장 위에서 내린다.

## 5. 실행 환경

| 항목 | 값 |
|---|---|
| 하드웨어 | Google Colab 무료 티어, Tesla T4 (VRAM 14.56GB) |
| Python | 3.13.15 |
| OS | Linux 6.6.122 / glibc 2.39 |

작업 PC의 GPU는 AMD Radeon RX 9070 XT인데, PyTorch의 GPU 가속은 NVIDIA CUDA 기반이라 이 카드로는
쓸 수 없다. 그래서 검증은 Colab T4에서 했다.

**다만 후보 3개 모두 가중치가 공개돼 있어 사내 PC나 사내 서버에서 동일하게 실행된다.**
검증 환경이 Colab이라는 사실이 "사진을 외부로 보내지 않는다"는 조건을 무너뜨리지는 않는다.
외부 API 후보는 그것이 구조적으로 불가능하다는 점이 차이다. (이 PoC의 샘플은 전부 공개 이미지라
실제 보안 문제는 발생하지 않는다.)
